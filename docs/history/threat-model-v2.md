# 威胁模型与安全边界

## 当前能够验证什么

完整手牌电路验证：指定网络/Registry/HandID 下，指定钱包授权的 Session Key 同意固定规则、roster 和全部随机性承诺；这些随机性导出确定牌序；所有动作有对应 Session 的有效签名并绑定所见公开状态和遮蔽底牌承诺；按完整引擎规则执行后，牌型、边池与最终筹码符合公开结果。真实完整 Proof 已在本地 EVM 验证，见验收记录。

这个保证依赖哈希、ECDSA、证明系统、可信工具链和实现正确。通过测试不表示无漏洞；本项目未经独立密码学/电路/合约安全审计，不是生产可用系统，也不能用于真实资金。

## ZK 无法排除的风险

| 风险 | 边界与措施 |
|---|---|
| 服务器泄牌、提前看未来牌 | 服务器按模型知道完整牌序；Proof 不反映其额外通信。需要运营隔离与审计；密码学隐藏需要 MPC/Mental Poker，当前没有实现。 |
| 串通、多账户、策略作弊 | 合法动作可以来自串通策略，执行正确性证明不能识别意图。 |
| 服务器选择性中止 | 看完种子或牌后可停机、不收包、不发布证明。客户端外部保存 Manifest 和签名收据可取证已承诺的牌局，但一笔结束交易无法强制完成或惩罚。 |
| 玩家拒绝 Reveal | 缺席整手中止，不以 0 种子补齐，不重抽同一 HandID。没有押金惩罚。 |
| 日志分叉、隐瞒开局 | 必须在 Reveal 前核对全部同伴 Consent，并外部保留服务器收据；服务器数据库和自报时间不是可信时间源。未被外部观察的中止不能被证明不存在。 |
| 超时与网络分区 | 服务端能记录超时/中止，链上执行共同签署的截止时间；电路不证明现实消息发布时间或网络活性。没有自动代签 Fold。 |
| Session 私钥或客户端失陷 | 有效签名不区分真实用户和窃取者。内存密钥、授权期限、桌/域限制、钱包撤销和加密备份降低风险，不能防止恶意客户端代码签署未展示给用户的状态。 |
| 撤销与过期历史 | 服务端在线执行会话撤销与时效，数据库锁避免撤销/接受竞态；链上无法知道未上链的撤销，Proof 不证明历史墙钟或所有链下事件。旧有效签名在截止前仍可能由第三方整理成证明。 |
| 结束后的牌隐私 | ZK Proof 本身隐藏 witness，但完成后下载的 Audit 主动披露全部种子/牌；发布它会丧失整手牌隐私。 |

## 已实现的防护

- 钱包 EIP-712 授权绑定 chainId、Registry、TableID、钱包、Session Key、nonce 和期限。原会话撤销后重试授权不能重新启用。域内 nonce 唯一；已接受动作相同重试幂等，冲突序列拒绝。
- serverCommit 先发布，再收玩家 Commit；承诺集合冻结后每位玩家签同一 Manifest，客户端验全部 peer 授权/Consent 后 Reveal。每手生成新玩家种子，至少一个诚实未提前揭示的种子在哈希假设下防止服务器事后选择牌序。
- 洗牌不仅约束 52 张牌的排列，还约束种子到全部卡片优先级及严格排序。Hash-sort 碰撞概率界 `1326/2^256`，不是绝对无偏声明。选择性中止可使最终完成样本发生偏差。
- 动作签名绑定实际观察；底牌承诺由玩家种子遮蔽，避免公开日志暴露底牌枚举。服务/Noir 独立回算同一状态。
- 私有快照 AES-GCM 加密，手牌 ID 作为关联数据；公开 Redis 缓存和 HTTP 公共状态不含种子/牌序/Hole。恢复需要持有该钱包的有效授权，只给该钱包 Hole。
- 持久化 ACK 在 Postgres 事务提交后生成响应；快照/签名日志版本原子更新。恢复检查收据链、手牌身份和光标；第 3 动作后服务器重启的完整九人测试通过。
- 合约公开输入绑定实际链和合约自身地址；初末筹码/身份/协议承诺/截止进入真实证明。Digest 无损 128 位拆分，重复手牌拒绝，正常只提交一笔结果交易，无代币接口。
- 工具固定版本与生成产物指纹防止意外错配。标准 EVM 合约大小限制保留，部署显式链接 Transcript 库。

## 验证范围与待办

当前有 Go 单元/规则/竞态/模糊/牌型穷举，SDK 签名和加密备份测试，Noir 原语正负测试、40 组 2–9 人完整 Go/Noir 差分轨迹、完整 witness 签名/种子/牌序/下注/输出篡改测试、真实 UltraHonk Proof、本地 Registry 单笔登记和恶意公开输出拒绝。完整本地测试不替代以下验证：

- 独立电路约束完整性与协议组合审计；固定工具链/可信发布及证明系统升级审查。
- Amoy 部署、确认/重组处理、网络重试和公网 RPC 限流；当前没有测试网成功记录。
- 生产认证入口限流、建桌配额、DDoS/数据库资源限制、监控、灾备与密钥轮换/KMS。开发 Compose 的数据库口令与本地 Anvil 账户只用于本地，不应暴露到公网。
- 更广的分布式分区/存储故障注入。当前通过的服务重启、并发幂等与撤销测试不能代表所有故障。
- 高额实战手牌可能超过 64 动作，上限中止是显式协议限制；需要扩大静态关系或递归设计才可覆盖所有合法轨迹。
- 跨手筹码连续性、资金托管、罚没、自动续桌和链上争议均未实现，也不由当前 Registry 保障。

“可证明执行正确”不等于“服务器无泄牌、玩家无串通、服务器永不中止”，也不等于当前版本已获生产安全认证。
