# v3 威胁模型

## 能够证明

指定网络、Registry、HandID 和公钥玩家 ID 下：不可变签发者为某个 accountId/kind、Session Key、域、桌和期限签发了证书；该公钥确实对应公开 playerId，持钥者签署了证书摘要、共同 Manifest 和动作；种子导出精确洗牌，发牌、下注、牌型、边池、筹码与公开结果一致。真实完整 Proof 的本地验证见本轮验收。

playerId 为 `SHA256("ZKPOKER_PLAYER_V3"||publicKey.x||publicKey.y)`。服务器即使可以签发证书，也不能用其他公钥替换已入桌的 playerId。客户端必须核对自己持有的密钥、预期名单/规则、自己的随机性承诺以及全部 Consent。服务端只给出“证书有效”布尔值不能替代电路验签；本项目实际约束证书、持钥证明和公钥承诺。

## 身份与恢复边界

账号名到 accountId 的映射、密码验证和游客登录由认证服务负责；ZK 不证明某个真人输入过密码，不提供 KYC、反女巫或去中心化账号所有权。服务器可以创建虚假账号或为账号名声明新的公钥，但不能在公开 playerId 不变时伪造原客户端的签名。用户应保留自己的 playerId、Manifest 和签名收据；仅看一个昵称不等于核对公钥身份。

账号重新登录允许服务为同一 accountId 的历史读取签发新 Session；正在进行的原手牌动作仍由原 Session 签名。游客登录 Cookie 丢失且无备份时无法找回同一身份。当前没有邮件/短信找回、第三方登录或 Passkey。加密备份含私钥和种子，应像凭证一样保护；私钥不存 localStorage，服务器不保存客户端私钥。

服务端在线执行到期、撤销和 nonce 唯一性；链上不知道未上链的撤销和真实消息时间。已持有有效签名或泄露密钥的第三方仍可能在 hand 截止前整理证明。若要求链上即时撤销，需要额外链上状态/交易，不在当前只记录结果的 Registry 中。

## 不能由 ZK 排除

| 风险 | 现状与边界 |
|---|---|
| 服务器泄露底牌/未来牌 | 服务器按模型知道整副牌，额外通信不进入执行证明；需要运营隔离，密码学隐藏需 MPC/Mental Poker。 |
| 串通、多账户、虚假账号 | 合法签名动作可以来自串通策略；注册不证明真人身份。 |
| 服务器选择性中止 | 看完牌后可以停机或不发布 Proof。外部保留 Manifest/ACK 可证明已有承诺，但一笔结束交易不能强制完成或罚没。 |
| 玩家拒绝 Reveal | 整手中止，不以 0 或重抽代替，缺少经济惩罚。 |
| 日志分叉和时间 | 必须在 Reveal 前验全部共同 Consent 并外部留存收据；服务器自报时间和数据库不能证明未公开中止不存在。 |
| 客户端失陷 | 密钥泄露或恶意 UI 可签署未经人理解的内容。观察摘要只能约束诚实客户端对收到数据的签名，不能证明屏幕实际展示。 |
| 可用性、网络分区 | ZK 不强制收包或完成牌局。协议可超时中止，不能伪造玩家 Fold。 |
| 结束后的隐私 | Proof 隐藏 witness；完整 Audit 则主动披露全部种子、牌、身份凭证，应只在完成后有意公开。 |

## 已验证防护

- 账号 Argon2id 哈希、随机 salt、token 仅哈希存储、HttpOnly/SameSite Cookie、Secure 配置、同源 JSON 写入检查、基本登录限流及两个并发派生上限。
- 伪造 accountId/kind/issuer 被拒绝；即使签发者重新签名，也不能为另一公钥冒充原 playerId；nonce 冲突、过期及撤销重放不能复活。
- Commit 集合冻结，全部 Consent 验签后才 Reveal；种子不跨手复用；实际 hash-sort 全约束，碰撞界 `1326/2^256`，不声称绝对无偏，选择性中止仍能偏置完成样本。
- 签名绑定实际公开牌面、筹码和遮蔽底牌；客户端检查牌数/整数/不同牌，避免补零歧义。有效签名的非法 Check、Short Raise、错误牌面和底牌均经过负测。
- Postgres 原子版本/收据/加密快照，服务器密钥持久化；Redis 公开缓存；恢复检查完整日志链和光标，私有读取按 accountId 验权限。
- 44 个公开字段无损绑定玩家公钥 ID、初末筹码、承诺、截止、实际链/合约与不可变签发者；真实生成 Verifier，正常大小限制，一手一笔登记，重复手牌拒绝。
